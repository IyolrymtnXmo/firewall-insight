Gateway Health

Interface state, cluster roles and software build, read over the read-only Gaia API. This is not monitoring — it is one reading at one instant. A gateway that did not answer produces no findings, which is not the same as producing none, so it is reported as a finding of its own. Needs GAIA_ENABLED in .env.

Compliance

A profile is a YAML file you own, listing the checks you have decided apply to your estate. This application ships no baseline as authority — the profiles below are starting points, and every check reports the clause it came from, or is labelled a house rule when it has none. There is no compliance percentage: a single number would have to price an unverifiable check, and every available price misleads.

Policy Diff

What changed between two audits. Rules are matched by their Check Point uid, never by rule number, so inserting one rule does not report every rule below it as rewritten. Capturing a snapshot writes one JSON file to this machine; nothing is sent to the Management Server but the same read-only show-* calls every other page makes.

Network Mapping

Logical topology only. Physical cabling, switches and live routing are not inferred. Load with Routing does not change that: it reads each gateway's routing table over the read-only Gaia API rather than inferring one — a snapshot at read time, not a live view — and needs GAIA_ENABLED in .env. Route entries the reader could not parse are counted and named, never dropped.
